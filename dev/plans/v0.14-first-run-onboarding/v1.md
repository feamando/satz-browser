## 1. Problem & Goal
When a user opens Satz Browser on a fresh installation with zero existing profiles (`profiles.length === 0`), they currently see a generic "Unlock profile" modal and an unready `gemma-4-e4b` default model state. We want a simple, optional-first onboarding flow powered out of the box by shipped Planck + heuristic instructions:

1. **Profile Entry (`profiles.length === 0`):**
   - **Create a new profile** (name + 6-digit PIN -> creates encrypted `vault.enc` & transitions to Model Setup).
   - **Upload an existing profile** (`.satzprofile` import reusing `renderProfileUploadSectionHtml` & `needLocalPin` flow -> drops user directly into their restored workspace without forced new-profile model setup).
   - **Demo without a profile** (dismisses gate into working Demo mode backed by shipped Planck + heuristics, with one-click entrypoints to create/upload a profile or replay the tour later).
2. **Model Setup (only after Create a new profile):**
   - Explains that Planck + heuristics already handle web answers, search, and mail classification locally.
   - Offers two optional generative paths:
     - **Cloud API key** for an existing supplier (`Gemini`, `Anthropic`, `OpenAI`, `Mistral`) using `sidecarUpdateModelConfig` + live model discovery, storing keys in encrypted `vault.enc`.
     - **Local model download** featuring Gemma (`google/gemma-4-E4B-it`, `google/gemma-3-4b-it`, with HF license/token hint) plus ungated compact starter alternatives (`Qwen 2.5 1.5B`, `SmolLM2 1.7B`) or linking an existing local model folder, using `sidecarStartHfDownload` + background polling.
   - Includes a **Skip for now (use Planck + heuristics)** exit at any point.
3. **Interface Click-Through Tooltips (5 steps):**
   - Drops the user into the live workspace and anchors 5 sequential click-through tooltips in the left rail:
     1. **Email setup** (`conv-mail`): Explains Satz's unique AI-filtered email setup (`Inbox`, `Pings`, `Orders`, `Promos`) + local extraction.
     2. **News & Topics** (`conv-news`): Explains how to configure News & Topics via News Settings, curated RSS feeds, and Perspectives.
     3. **Conversations** (Conversations header / New): Explains conversation-centric browsing (live tabs, Focus Mode, 2-4 tile Compare View, grounded chat).
     4. **Bookmarks** (Bookmarks section): Explains saving & local Brain indexing of bookmarked sites.
     5. **Settings** (`#rail-open-knowledge-btn`): Explains profiles/vault, model routing, Mail/OAuth, language, and replaying the tour.

## 2. Architecture & Changes
1. **Frontend State (`src/state.ts`, `src/types.ts`):**
   - Add onboarding state fields: `onboardingStep: "welcome" | "models" | null`, `onboardingModeTab: "create" | "upload" | "demo"`, `onboardingModelTab: "cloud" | "local"`, `onboardingCloudProviderId: string`, `onboardingLocalRepoId: string`, `onboardingValidationError: string`, `onboardingDemoMode: boolean`, `onboardingTourStep: number | null`.
   - Add `hasAnyGenerativeModelConfigured(cfg)` and update `syncConfiguredChatModel` so missing Gemma + zero custom local/cloud models automatically selects `"planck3 (web)"` instead of sending unconfigured `"gemma-4-e4b"` requests.
2. **Onboarding & Tooltip Tour Module (`src/onboarding.ts`):**
   - Render & bind the 2-step onboarding modal (`#onboarding-overlay`) reusing `renderProfileUploadSectionHtml("onboard")` and `bindProfileUploadSectionEvents`.
   - Render & position `#onboard-tour-popover` anchored next to the 5 left-rail targets (`[data-onboard-anchor="mail" | "news" | "conversations" | "bookmarks" | "settings"]`), auto-expanding rail accordions, scrolling into view, highlighting active target, and respecting `[dir="rtl"]`.
3. **Shell, Rail, Start, Settings & Profile Gates (`src/main.ts`, `src/rail.ts`, `src/start.ts`, `src/knowledge.ts`, `src/mail.ts`, `src/news.ts`, `src/drives.ts`, `src/tabs.ts`):**
   - Ensure `conv-mail` alongside `conv-news`, `conv-drives`, `conv-settings` on startup (`src-tauri/src/db.rs` `DbState::init()` + `src/main.ts` `initApp()` before `refreshLists()`).
   - Wire `onImportProfileFile` through `mail.ts`, `news.ts`, and `drives.ts` inline profile gates so `.satzprofile` upload works identically from every locked surface.
   - Update `start.ts` & `rail.ts` to show clean Demo Mode status when `profiles.length === 0 && !unlocked` with buttons to set up/upload a profile or start the tour.
   - Add "Replay onboarding tour" control in Settings (`src/knowledge.ts`).
   - Hide child native webviews cleanly while onboarding modal or tooltip popover is visible (`src/tabs.ts`).
4. **Sidecar Robustness (`sidecar/satz_models.py`):**
   - Guard `os.chdir(self.sgs_root)` in `run_answer()` with `if self.sgs_root.exists():` so Planck + heuristics works reliably even when `../sgs` is absent.
5. **Styling & i18n (`src/design-system/components.css`, `src/i18n/catalog.ts`):**
   - Add tokenized CSS (zero raw hex) for `.onboard-modal`, `.onboard-step-pills`, `.onboard-choice-grid`, `.onboard-tour-popover`, and `.onboard-anchor-active` with RTL support.
   - Add all new copy to `src/i18n/catalog.ts` with zero em/en dashes.
