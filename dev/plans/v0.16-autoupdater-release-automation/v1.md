# Autoupdater & Automated Cross-Platform Release Pipeline (`v0.16` - v1)

- **Owner:** Nikita Gorshkov
- **Status:** Complete
- **Target Version:** `v0.5.1`
- **Related Docs:** [[../../docs/RELEASE_RUNBOOK.md]] · [[../../agents/release_management.md]] · [[../v0.10-standalone-packaging/v2.md]]

## 1. Problem & Goal
End-to-end binary auto-updates across Windows and macOS currently fail or stall between git pushes and running desktop installs because of four gaps:
1. `.github/workflows/release.yml` marks GitHub releases `releaseDraft: true` and `prerelease: true`, whereas `tauri.conf.json` queries `https://github.com/feamando/satz-browser/releases/latest/download/latest.json`, which GitHub skips for both drafts and prereleases.
2. Parallel Windows + macOS `tauri-action` jobs have no preflight parity/security validation, no shared pre-created draft ID to eliminate parallel release-creation races, and no post-matrix `latest.json` verification before promoting live.
3. Normal pushes to `main` had no fast multi-OS CI build check, allowing macOS-only Rust compile regressions (e.g., `objc2::AnyThread`) to surface only at release time.
4. Client installation in `src/updater.ts` passed an unawaited `async` callback to `downloadAndInstall()`, risking installer file locks on Windows while stopping the Python sidecar asynchronously.

Goal: Make tag-triggered releases (`v*` / `workflow_dispatch`) validate parity/weights/security, build and sign both OS targets into one release, verify `latest.json`, publish cleanly to `/releases/latest/download/latest.json`, and upgrade running clients deterministically with sidecar shutdown awaited before install.

## 2. Architecture & Changes
1. **Continuous Multi-OS Verification (`.github/workflows/ci.yml`):**
   - Runs on `push` to `main` and `pull_request` across `windows-latest` and `macos-latest`: `npm ci`, `npm run build`, `node scripts/i18n_extract.mjs --check`, `cargo test --manifest-path src-tauri/Cargo.toml`, and `scripts/security_audit.py scan --mode all`.
2. **3-Stage Atomic Auto-Updater Release Workflow (`.github/workflows/release.yml`):**
   - **`prepare-release` (`ubuntu-latest`):** Validates tag parity & weights & security via `scripts/release_version.py ci-preflight`, creates/reuses one GitHub Draft Release, and outputs `release_id`, `tag_name`, and `version`.
   - **`build-tauri` (`windows-latest` + `macos-latest`):** Stages relocatable Python 3.12 runtime + `sidecar/` (`scripts/prepare_sidecar_bundle.py`) and runs `tauri-apps/tauri-action@v0` against `releaseId` with `releaseDraft: true`, `prerelease: false`.
   - **`publish-release` (`ubuntu-latest`, after both OS builds):** Downloads `latest.json`, validates matching version, `.sig` signatures, and both `windows` + `darwin` entries via `scripts/release_version.py verify-updater-manifest`, promotes release (`--draft=false --latest`, `--prerelease=false` unless requested), and polls `/releases/latest/download/latest.json`.
3. **Deterministic Sidecar Shutdown During Update (`src/updater.ts`):**
   - Switch `downloadAndInstallAppUpdate()` to sequential `await update.download(...)` -> `await invoke("prepare_for_update")` -> `await update.install()` -> `await relaunch()`.
4. **Release CLI & Git Sync Automation (`scripts/release_version.py`, `scripts/git_sync.py`):**
   - Sync `package-lock.json` on version bumps in `release_version.py`.
   - Add `ci-preflight` and `verify-updater-manifest` subcommands to `scripts/release_version.py`.
   - Add optional `--bump <major|minor|fix|patch|X.Y.Z>` + `--release-notes` support to `scripts/git_sync.py sync`.
5. **Runbook, Protocol, Skill & Unit Tests:**
   - Update `dev/docs/RELEASE_RUNBOOK.md`, `dev/agents/release_management.md`, and `dev/agents/skills/satz-release-manager/SKILL.md`.
   - Add tests in `sidecar/test_dev_brain.py` for workflow YAML validity, `ci-preflight`, and `verify-updater-manifest`.
