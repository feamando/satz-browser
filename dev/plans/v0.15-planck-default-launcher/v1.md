## 1. Problem & Goal
On less powerful machines, preloading or defaulting to `gemma-4-e4b` during startup and onboarding consumes heavy CPU/RAM or triggers unwanted model-loading attempts. Until the user explicitly adds Gemma (or another local/cloud model) to their configuration, Satz Browser must launch and operate on shipped **Planck** (`planck3 (web)` / `xreader_planck` / `planck13` / deterministic Settings & News handlers) out of the box.

Goals:
1. Disable unconditional Gemma preload on startup across Rust (`src-tauri/src/lib.rs`) and Python (`sidecar/satz_models.py`), and only preload a local LLM if explicitly configured in `satz_meta` (`model_role_chat`).
2. Default unassigned chat and News role slots (`chat`, `effective_chat`, `news_planner`, `news_capture`, `news_analyzer`) to `"planck3 (web)"` / `"template"` in backend and frontend until a user adds Gemma, another local LLM, or a cloud API key.
3. Ensure all basic flows (onboarding, Settings chat cards/status, News startup/digest/questions, tab/mail reading) run smoothly on Planck without forcing `"gemma-4-e4b"` rewrites or returning empty `"(no response)"` replies.

## 2. Architecture & Changes
1. **Rust Shell (`src-tauri/src/lib.rs`):**
   - Set `SatzSettings::default().preload_gemma` and serde default to `false`.
2. **Sidecar Runtime & Preload (`sidecar/satz_models.py`):**
   - Default `--preload-gemma` to `False`; centralize `resolve_preload_local_llm_id()` so preload only runs when `satz_meta` explicitly assigns `model_role_chat` to an installed local generative LLM (`"gemma-4-e4b"` or `"local:..."`).
   - Update `get_model_management_config()` and `get_doctor()` so unassigned defaults resolve cleanly to `"planck3 (web)"` / `"template"` (upgrading `effective_chat` only when user-configured cloud keys or explicit local models exist).
   - Handle `"planck3 (web)"`, `"planck (reader)"`, `"hertz (reader)"`, and `"template"` cleanly inside `stream_chat()` (skipping Gemma preload/lookup for Settings/News Settings and answering chat/tab/mail/web requests via `run_read`, passage extraction, or `run_answer`).
3. **Settings Deterministic Fallbacks (`sidecar/satz_tools/fallback.py`):**
   - Expand `maybe_fallback_settings_cards()` to cover profile listing/unlocking, model role inspection, Drives status, action providers, and a safe Settings summary/help fallback so Settings chat always produces actionable output without an LLM.
4. **News Pipeline (`sidecar/satz_news.py`):**
   - Treat non-generative Planck/reader roles cleanly alongside `"template"` across `_build_news_writer_spec()`, `get_perspectives()`, and `synthesize_followed_story()`.
5. **Frontend (`src/state.ts`, `src/main.ts`, `src/knowledge.ts`, `src/api.ts`):**
   - Default `selectedModel` and offline role fallbacks to `"planck3 (web)"`, remove `isSettingsConv` forced `"gemma-4-e4b"` override in `handleSendChatMessage()`, route open-tab/mail/drives Planck queries through `sidecarStreamChat`, and include `"planck3 (web)"` / `"template"` options in Settings -> Models role selectors.
